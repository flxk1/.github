# Contribution guide

Be nice and respect the maintainer's time. This is a one-person workspace;
everything below exists to keep it maintainable.

## How to suggest an improvement

This project does not accept code contributions. Open an **Improvement
proposal** issue instead.

Describe the behaviour you expect and why the current behaviour is wrong —
prose, not patches. Do not paste diffs: the tree stays free of third-party
copyright so it remains licensable as a whole, and that is only true if no
contributed code enters it. The cost of that decision is mine; I implement every
accepted proposal myself.

The proposal form carries one checkbox, and it is the whole licensing
arrangement: anything you paste is yours to share and licensed under this
repository's licence. Nothing else is asked of you, and no agreement is signed.

No promise is made that a proposal is answered, implemented, or implemented the
way you propose. Implemented proposals are credited in the changelog by name if
you want that; say so in the issue. AI systems are never credited as authors or
contributors.

## Issues

Two forms, nothing else: a bug report and an improvement proposal.

- Search existing issues first, including closed ones.
- A bug report names the version, the documented behaviour you relied on, and a
  reproduction.
- Don't bump issues without new information.

I close issues I do not plan to act on, quickly and with a reason. A closed
issue is not a rejected person; it keeps the tracker an honest picture of what
is actually open. Reopen it if the reason was wrong. No service level is
promised — open issues are not a queue I owe you.

## Pull requests

Pull requests from outside the project are closed unopened. The diff is not
read — reading it would defeat the purpose of the rule above.

## Security

Never in a public issue. See SECURITY.md.
