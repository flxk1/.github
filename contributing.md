# Contribution guide

Be nice and respect the maintainer's time. This is a one-person workspace;
everything below exists to keep it maintainable.

## How to suggest an improvement

This project does not accept code contributions. Send improvement proposals to
**contributions@felixkrone.de**.

Send prose, not patches: describe the behaviour you expect and why the current
behaviour is wrong. Do not send diffs, patches, or code snippets — I will not
read them, and mail containing them is deleted unread with a short note asking
for a description instead.

This is not gatekeeping about quality. The tree stays free of third-party
copyright so it remains licensable as a whole; that is only true if no
contributed code ever enters it. The cost of that decision is mine: I implement
every accepted proposal myself.

By sending a proposal you confirm it is yours to send and contains nothing
confidential. Ideas are not protected by copyright; should your mail
nevertheless contain protectable text and I use it, you grant permission to use
it under this repository's licence and any other terms. Say so in the mail if
you do not want that — then I will not use it.

No promise is made that a proposal is answered, implemented, or implemented the
way you propose. Implemented proposals are credited in the changelog by name if
you want that; say so in your mail. AI systems are never credited as authors or
contributors.

## Issues

Bug reports only — everything else goes to contributions@felixkrone.de.

- Search existing issues first, including closed ones.
- A bug report names the version, the documented behaviour you relied on, and a
  reproduction.
- Don't bump issues without new information.

I close issues I do not plan to act on, quickly and with a reason. A closed
issue is not a rejected person; it keeps the tracker an honest picture of what
is actually open. Reopen it if the reason was wrong. No service level is
promised — open issues are not a queue I owe you. Repositories with issues
disabled take reports by email.

## Pull requests

Pull requests from outside the project are closed unopened. The diff is not
read — reading it would defeat the purpose of the rule above.

## Security

Never in a public issue. See SECURITY.md.
